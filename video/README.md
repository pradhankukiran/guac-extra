# video

Rust library that turns a display's changed pixels into H.264 for guacd.
The pipeline is voxl's (https://github.com/tembo/voxl, MIT), separated
from voxl's screen capture and WebSocket server:

| Module | What it does | voxl origin |
|---|---|---|
| `convert.rs` | BGRX to I420 with libyuv, split across threads | `src/convert.rs` |
| `encoder.rs` | x264 wrapper tuned for low-latency desktop video | `src/encoder.rs` |
| `stripes.rs` | Horizontal stripes, each its own H.264 stream and thread | `src/video.rs` |
| `governor.rs` | Fans a stripe out to more threads under sustained load | `src/video.rs` |
| `quality.rs` | Keeps window drags and scrolling at the configured quality | `src/video.rs` |
| `refine.rs` | Paint-over: re-sends still areas at high quality | `src/video.rs` |
| `flow.rs` | Per-viewer acks, flow control, adaptive bitrate | `src/hub.rs`, `src/video.rs` |
| `session.rs` | Decides when a frame is due and encodes it | `src/video.rs` |
| `capi.rs` | C API for guacd | new |

Differences from voxl:

- No screen capture: guacd passes pixels and changed rectangles.
- No clock: every call takes `now_ms` from the caller, so timing logic is
  tested without waiting.
- No networking: the library says which viewers get each frame; guacd
  sends it.
- Odd display sizes are padded to even for x264.
- Still stripes are skipped on sharpening passes when nothing in them is
  left to sharpen.
- Faster bitrate recovery after a link gets faster (decision 0006).

## C API

Header: `include/guac_extra_video.h` (generated by cbindgen; do not edit).

```c
GxConfig cfg;
gx_config_default(&cfg);                 /* then adjust fields */
GxEncoder* enc = gx_encoder_new(&cfg, width, height, now);

uint32_t viewer = gx_encoder_add_viewer(enc, now);   /* per user */

/* whenever the display changes */
gx_encoder_update(enc, pixels, stride, rects, n_rects);

/* whenever a frame could be sent, and at gx_encoder_next_deadline_ms() */
if (gx_encoder_encode(enc, now) == 1) {
    for (size_t i = 0; i < gx_encoder_frame_parts(enc); i++) {
        GxPart part;
        gx_encoder_frame_part(enc, i, &part);  /* stripe, y, height, keyframe, data, len */
        /* send part.data to each gx_encoder_frame_recipients() viewer */
    }
}

/* from each viewer */
gx_encoder_ack(enc, viewer, frame_id, now);   /* frame decoded */
gx_encoder_rtt(enc, viewer, rtt_ms);          /* round trip measured */
gx_encoder_request_keyframe(enc, viewer);     /* decoder reset */

gx_encoder_remove_viewer(enc, viewer);
gx_encoder_free(enc);
```

Rules:

- One encoder per display surface and size. Create a new one on resize.
- Do not use one encoder from two threads at once.
- Part data stays valid until the next `gx_encoder_encode()` or
  `gx_encoder_free()`.
- The log callback may run on the library's encoder threads.

## Build and test

In Docker (no host packages needed):

```sh
make video-test
```

This runs on Ubuntu 24.04: 20 unit tests, 8 pipeline tests (including an
ffmpeg decode check of every frame), and a C program that uses only the
C API (`tests/c/smoke.c`) and checks its output decodes.

On the host, install the packages first:

```sh
sudo apt install libx264-dev libyuv-dev libclang-dev ffmpeg
cargo test --release
```
